# Автономная навигация: ROS 2 Humble + Gazebo Fortress

Робот едет из A **(-5, -3 м)** в B **(5, 3 м)**, строит карту по 2D-лидару, планирует объезд препятствий и останавливается у GPS-точки. Камера RGB-D, имитирующая Orbbec Astra, дополнительно контролирует препятствия впереди. Доступны собственный робот, **TurtleBot3 Burger** и **Jackal**, а также три мира: полоса препятствий, склад и открытая площадка.

## Запуск

Платформа: **Ubuntu 22.04, ROS 2 Humble, Gazebo Fortress / Ignition Gazebo 6**. Установите ROS Humble и настройте официальный репозиторий OSRF для Fortress, затем выполните:

```bash
./scripts/install_dependencies.sh
./run.sh
```

Выбор робота и мира:

```bash
./choose.sh
# Или явно:
./run.sh robot:=jackal world:=warehouse
./run.sh robot:=turtlebot3 world:=outdoor
```

Одна команда запускает симулятор, мосты датчиков, TF, локализацию, построение карты, навигацию, отдельный узел безопасности, независимую проверку результата и RViz. Зелёная зона — старт, синяя — финиш. На полосе препятствий робот следует прямо к GPS-точке B; на складе и открытой площадке сначала посещает GPS-точку (-4,5; 1,5 м), отмеченную золотым, затем B. Это последовательные waypoints, разрешённые заданием. Ctrl+C завершает работу.

Для запуска без окон, но с программным рендерингом датчиков:

```bash
xvfb-run -a env ROBOT_DEMO_SOFTWARE_RENDERING=1 ./run.sh gui:=false rviz:=false
```

## Реализация

- **Локализация:** GPS → локальная система ENU WGS84; одометрия прогнозирует перемещение, IMU задаёт направление, фильтр корректирует положение по GPS. Единственный владелец TF `map → odom` — узел локализации.
- **Карта:** изначально неизвестная сетка 0,1 м. Лучи лидара обновляют свободные клетки и занятые конечные точки по логарифмическим шансам. Известные координаты препятствий и истинная поза Gazebo не передаются узлам управления. Это построение карты с GPS-локализацией, а не SLAM с сопоставлением сканов.
- **Планирование:** A* с восемью соседями, запретом срезания углов и проверкой сокращённых сегментов. Препятствия расширяются на радиус робота и запас. Новые наблюдения вызывают перепланирование.
- **Управление:** последовательное достижение GPS- или мировых точек; допуск 0,20 м; нулевая скорость при завершении, паузе или отсутствии пути.
- **Безопасность:** независимый `velocity_guard` проверяет лидар/глубину, свежесть датчиков и команд. Таймер использует монотонное время: остановка часов симуляции также приводит к нулевой команде.
- **Проверка:** отдельный монитор использует истинную позу и контакты Gazebo исключительно для измерения ошибки финиша, запаса до препятствий и столкновений.

В Fortress применяется нативная система **NavSat + ros_gz_bridge**, публикующая `NavSatFix`. Указанный в задании `gazebo_ros_gps` относится к Gazebo Classic. Выбрана разрешённая заданием альтернатива Ignition, и это различие явно задокументировано. Камера является функциональной эмуляцией RGB-D, а не калиброванной копией конкретной модели Astra.
