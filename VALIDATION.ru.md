# Измеренные результаты проверки — v2.0.0

**Язык / Language:** Русский · [English](VALIDATION.md) · [Главная страница](README.ru.md)

Это реальные запуски физики и датчиков Gazebo на **ROS 2 Humble + Gazebo Fortress**, записанные 5 октября 2026 года. Истинная поза и контакты симулятора используются только независимой проверкой и не передаются навигации. Исходники и конфигурация сохранены вместе с результатами. Перевод документации не изменяет реализацию и измерения v2.0.0.

## Тесты и внесение отказов

**Пройдены 20 чистых Python-тестов**, затем проверены синтаксис компиляцией, линтер Ruff и форматирование. [Вывод проверки](evidence/unit_tests_v2.txt). Проверяются карта/очистка лучами, начальное неизвестное состояние, некорректный лидар, форматы/шаг строк/порядок байтов глубины, ENU/фильтр/выбросы GPS, углы/расширение/выход из запаса планировщика и тормозной запас.

Испытания отказов наблюдают фактический поток `/cmd_vel` и требуют, чтобы нулевые команды сохранялись. Время реакции измерено по реальным часам от внесения отказа до первой наблюдаемой нулевой команды; это результат конкретного испытания, а не гарантированный предел для любых систем.

| Отказ | Первая нулевая команда (с) | Предельное время теста (с) | Результат |
| --- | ---: | ---: | --- |
| pause_service | 0.048 | 0.75 | [ПРОЙДЕНО](evidence/safety/pause_service.json) |
| clock_stall | 0.398 | 0.75 | [ПРОЙДЕНО](evidence/safety/clock_stall.json) |
| controller_exit | 0.500 | 0.75 | [ПРОЙДЕНО](evidence/safety/controller_exit.json) |
| gps_loss | 1.949 | 2.50 | [ПРОЙДЕНО](evidence/safety/gps_loss.json) |

Идентификаторы отказов: `pause_service` — пауза миссии через сервис; `clock_stall` — остановка часов симуляции; `controller_exit` — завершение процесса контроллера; `gps_loss` — потеря моста GPS.

[Полные трассы команд и состояния контроля скорости](evidence/safety_summary.json). Узел контроля скорости не защищает от своего отказа, отказа компьютера или моста движения; реальному оборудованию нужны сторожевой таймер двигателя и аварийная остановка.

## Чистый контейнер

Чистое Docker-окружение зависимостей/сборки/выполнения успешно выполнило стандартную миссию собственного робота на полосе препятствий: **0.190 м** фактической ошибки финиша, **0.366 м** минимального зазора по окружности, **0** касаний препятствий, конечная команда **[0, 0]**, код завершения контейнера **0**. Образ собирает пакет и выполняет чистые тесты до запуска Gazebo.

[Отчёт миссии](evidence/clean_container/matrix/custom_obstacle_course.json) · [Журнал сборки](evidence/clean_container/build.log) · [Журнал запуска](evidence/clean_container/run.log) · [Состояние завершения](evidence/clean_container/container_state.json) · [ID образа](evidence/clean_container/image_id.txt) · [Версии](evidence/clean_container/versions.txt).

Проверенный образ использует Ubuntu 22.04, Python 3.10.12, библиотеку Fortress 6.18.0 и пакет Humble ros_gz_bridge 0.244.26. Dockerfile устанавливает пакеты из текущих apt-репозиториев, поэтому будущие версии могут отличаться; сохранённые версии/ID образа идентифицируют эту локальную проверку. [ci/github-actions.yml](ci/github-actions.yml) содержит шаблон аналогичной проверки для GitHub Actions. Удалённый CI не включён: GitHub отказал в загрузке workflow, поскольку текущая OAuth-авторизация не имеет разрешения `workflow`. Выполненная локальная проверка контейнера от этого разрешения не зависит.

## Видео и bag для воспроизведения

[Демонстрация длительностью 60 секунд](https://github.com/monijesuj/ros-gazebo-navigation-assignment/releases/download/v2.0.0/demo.mp4) записывает реальные окна Gazebo + RViz с подписями из текущего отчёта. Робот достигает B с фактической ошибкой **0.191 м** и **0** касаний препятствий. Карта по датчикам содержит **13053** наблюдаемые клетки. [Отчёт видеозаписи](evidence/hero_mission.json) · [Предпросмотр](evidence/demo_preview.png).

Кадры кодируются с частотой 12 кадров/с; 69.51 с реального времени захвата превращаются в 60.00 с воспроизведения (приблизительно 1.16× относительно реального времени). Производительность захвата меняется, а время симуляции учитывается отдельно. Данные датчиков и движение робота не вымышлены. [Метаданные времени](evidence/demo.json).

Необязательный ROS bag SQLite3 содержит **21 топик**, **75.055 с** временных меток симуляции, все топики датчиков/команд/карты/TF/состояния из [bag_info.txt](evidence/bag_info.txt), включая сохранённое описание робота и RGB-изображения. В конце записи и миссия, и независимая проверка имеют состояние `SUCCEEDED`, число касаний препятствий равно нулю, конечный `/cmd_vel` — нулевой. [Проверка bag без симуляции](evidence/bag_validation.json).

Bag поставляется отдельным архивом релиза, чтобы Git-репозиторий оставался небольшим. Подключите окружение рабочего пространства, откройте RViz с `src/robot_demo/config/demo.rviz` и `use_sim_time:=true`, затем выполните `ros2 bag play <bag-directory>` с тем же ROS domain. Bag содержит `/clock`; дополнительный источник часов воспроизведения не нужен.

## Интерпретация

Проверки подтверждают условия задания для трёх сохранённых миров. Они не подтверждают устойчивость в произвольном окружении, обработку динамических препятствий, реалистичную работу с шумными GNSS/IMU или аппаратную безопасность. Нативный NavSat Fortress — явно описанный эквивалент указанного по имени GPS-плагина Classic. Оценка работодателя, понимание кандидатом и соблюдение срока находятся вне автоматической проверки. [REQUIREMENTS.ru.md](REQUIREMENTS.ru.md) показывает каждый пункт и расположение его доказательств.
